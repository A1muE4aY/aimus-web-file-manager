# AWFM v0.1.0 — Computer Use 独立验收任务

你已经完成 AWFM v0.1.0 的开发。现在进入独立验收阶段。本阶段的重点不是继续开发功能，而是通过真实桌面交互验证交付物是否可用，并检验你在无人实时指导情况下使用 Computer Use（CU）的能力。

## 一、核心约束

1. 必须使用 Microsoft Edge 的 InPrivate（无痕）窗口完成所有浏览器端验收。
2. 必须实际使用 Computer Use 操作桌面，包括浏览器窗口、页面控件和交互反馈。不得仅通过 HTTP 请求、JavaScript 注入、CDP 直接操作 DOM、Playwright、Selenium 或其他纯自动化接口替代实际桌面交互。
3. 终端和脚本可以用于启动服务、查看日志、检查文件及辅助诊断，但不能代替本任务要求的桌面操作。
4. 不得仅凭代码、测试报告或 HTTP 状态码宣称功能通过。必须在实际界面中操作，并检查操作结果。
5. 不得修改已有测试结果、伪造截图或将未执行的操作报告为已完成。
6. 不得为了完成任务擅自降低安全要求、关闭安全机制或绕过应用正常流程。
7. 如果 CU 不可用、无法控制桌面、窗口无法识别或测试被环境限制阻断，必须记录实际障碍和已尝试的恢复方式，不得伪称成功。
8. 不要向我询问已经确定的技术选型。遇到非关键障碍时先自主诊断并尝试安全、可逆的解决办法；只有遇到必须由我提供的信息、授权或不可逆操作时才暂停询问。

## 二、验收任务

### A. 启动与环境识别

- 检查当前应用和服务的实际状态。
- 自主选择合理的方式启动或运行 AWFM。
- 打开 Edge InPrivate 窗口，进入本地 AWFM 页面。
- 确认页面实际显示正常，记录遇到的异常及处理过程。

### B. 界面交互

通过真实桌面操作完成以下任务：

- 打开连接管理界面，检查连接列表的显示状态。
- 使用界面控件打开连接配置流程，检查输入框、按钮、提示信息和页面切换是否正常。
- 检查至少一个文件列表交互，以及一个预览或对话框交互。
- 检查至少一个错误状态，例如缺少必要输入或连接失败时的界面反馈。
- 如果存在可安全使用的测试环境，通过界面完成一次真实文件下载或上传，并验证结果。

不得为了完成上传、下载而操作未经确认的真实用户文件。优先使用专门的临时测试目录和无敏感内容的测试文件。如果当前没有可用的远程测试环境，应完成其余项目，并明确标注文件传输验收受阻。

### C. 结果验证

- 检查每项操作在界面中的实际反馈。
- 对能够安全验证的操作，使用独立方式核对结果。
- 记录失败、重试、恢复及无法完成的项目。
- 保留真实桌面操作过程的录屏或截图证据；不得用人工合成的画面代替实际操作证据。

## 三、工作方式

请自主制定简短的执行计划并立即开始，不要再次生成大篇幅设计文档。

先完成环境检查，然后逐项执行。遇到问题时，优先观察当前桌面状态、识别原因并尝试合理的恢复方案。避免无意义地重复同一操作。

如果某项任务无法完成，继续执行不依赖该项的其他任务，不要因为单个非关键障碍而停止全部工作。

## 四、最终报告

完成后提交简明报告，包含：

1. 实际使用的 CU 操作方式。
2. Edge InPrivate 窗口的实际使用情况。
3. 每项验收任务的结果：通过、失败、受阻或未执行。
4. 哪些操作由真实桌面交互完成，哪些操作由终端或脚本辅助。
5. 遇到的主要问题、诊断过程和恢复措施。
6. 可供复核的录屏、截图、日志及文件路径。
7. 尚未验证的功能和限制。


## 五、虚拟机自主发现与启动测试（补充）

本次验收必须尝试使用 Computer Use，通过桌面界面发现并启动本机已有的 CentOS 虚拟机，将其作为 AWFM 的真实 SSH/SFTP 目标环境。

1. 自主识别桌面上的虚拟化软件和已有的 CentOS 虚拟机，不要预先假定虚拟机名称、文件路径、网络地址或当前运行状态。
2. 通过 VMware Workstation 的图形界面检查虚拟机状态，并在确认目标无误后启动它。不得创建新的虚拟机、删除或重置虚拟机、修改虚拟磁盘，或擅自更改网络模式。
3. 观察启动过程，并自主判断何时可以进行后续验证。可以使用终端检查网络连通性、SSH 服务状态和日志，但必须保留通过桌面界面启动虚拟机的实际证据。
4. 系统就绪后，确认实际网络地址及 SSH 可用性。不得仅凭发现一个 IP 地址就认定 SSH 已可用。
5. 使用 Edge InPrivate 窗口打开 AWFM，通过界面连接到真实 CentOS，执行目录浏览、测试文件上传和下载，并核对文件内容一致性。
6. 测试文件只能放在专门创建的临时目录中，不得覆盖、移动或删除用户已有文件。测试结束后，只清理本次创建且能够明确识别的临时文件。
7. 如果启动失败、需要用户登录、出现不明的 VMware 提示、需要管理员权限，或遇到可能影响虚拟机数据的操作，应暂停相关操作并报告具体障碍。不要猜测密码，不要绕过安全机制，也不要为了完成任务重置虚拟机。使用指定用户名登录：Aimu，若登录需要密码，请立即告诉我你需要人工操作。
8. 如果虚拟机无法启动，继续完成其他不依赖它的 CU 验收任务，并明确报告真实 CentOS 集成测试未完成，不得用 WSL 或模拟结果替代。
9. 最终报告必须区分：通过 CU 完成的操作、由终端辅助完成的检查、真实 CentOS 端到端结果，以及尚未完成的项目。
**验收原则：以实际执行证据为准，不以计划、代码存在、测试数量或自我评价作为通过依据。**
