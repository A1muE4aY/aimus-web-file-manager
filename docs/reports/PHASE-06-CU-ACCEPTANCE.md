### 1.1 「真实 CU 操作」与「终端辅助操作」的界线

任务书 `2.md:204` 要求「使用 Edge InPrivate 和真实桌面交互进行验收，不得使用直接 HTTP 调用、CDP、JavaScript 注入或浏览器自动化脚本替代被要求的 CU 操作」，`2.md:218` 允许终端做环境准备、日志查看与结果核对。本报告的划分：

- **真实 CU 操作**：在真实 Edge InPrivate 窗口上点按钮、勾选、填表单、看提示、看列表——输入经桌面层投递（UI Automation 的 Invoke/Value 模式、窗口消息或前台键盘事件）落到该窗口，浏览器收到的是真实输入事件。**全程没有使用 CDP、没有 JavaScript 注入、没有替页面直接调 HTTP 接口**。
- **终端辅助操作**（只用于准备与核对，均在正文里标明）：用 `ssh` 造测试文件 / 改远端文件 / 删远端文件、用 `ssh-keygen` 与 `ssh-keyscan` 独立复核主机指纹、用 `sha256sum` 独立复核远端哈希、读取服务端日志 `logs/awfm.log`、查看 `.temp/cu-v011/config.json` 核对配置落盘。
- **已知差异（如实记录）**：点击与键入由桌面 CU 驱动完成，不是人手在键盘鼠标上操作；因此「按钮被真实鼠标点中」这一点由驱动的事件投递保证，而**人工手感类问题**（如拖拽体验、连点抖动）本报告不作结论。

## 4. 过程中发现的缺陷与处理

### 4.1 CU 期间发现并已修复的前端缺陷（两处）

1. **对话框外的点击 / Esc 会静默丢掉未保存的修改**（CU 早期误点对话框外面时真实丢过一次内容）：`frontend/assets/js/modal.js` 原先只有「取消」按钮走脏检查，Esc 与 `#modal-backdrop` 的点击直接关闭。修复后 `openModal` 支持 `onRequestClose`，Esc / 点外面 / 右上角 × / 「取消」四条路径统一先问「有未保存的修改，确定放弃吗？」（检查函数抛错时按「不许关」处理）；`frontend/assets/js/edit.js` 传入 `onRequestClose: cancelNow`。回归用例 `tests/e2e/test_browser_edit.py` 的 `test_backdrop_and_escape_ask_before_discarding`。
2. **关掉写权限后行内按钮不立刻置灰**：工具栏「上传」立即变灰，但列表行里的「重命名 / 压缩 / 删除」要等列表重渲染才更新。修复为 `frontend/assets/js/app.js` 的 `toggleWrite()` 在 `updateToolbar()` 之后补一次 `files.render()`。回归用例同文件的 `test_write_buttons_follow_a_live_write_toggle`。

### 4.2 回归测试顺带发现的服务端缺陷（一处）

`app/services/search.py` 的 `SearchRegistry._prune_locked()` 原先按 `(finished_at, sid)` 排序淘汰旧的搜索记录，而本机 `time.time()` 的粒度粗到连续 50 次调用取回同一个值（实测 49 个差值为 0），排序因此退化成按随机的 `search.id` 排——「淘汰最旧的一次」变成「淘汰任意一次」，单元用例 `tests/unit/test_search.py` 的 `test_old_finished_searches_are_pruned` 在四层全量回归里随机失败了一次。探针 `.temp/probe_prune_order.py` 在旧实现上 40 轮错 26 轮（21 轮淘汰了较新的一条，5 轮最旧的一条没被淘汰），修复后 0/40。修复：排序键改用 `_searches` 的插入次序兜底；同时把该用例从「1 ≤ 保留数 ≤ 6」加强为「恰好保留最近 3 次，且 `ids[0..2]` 一定查不到」。
