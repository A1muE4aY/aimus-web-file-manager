# AWFM 用户手册

**版本**：v0.1.3　**文档日期**：2026-10-17（手册主体写于 v0.1.0/v0.1.1；v0.1.2 增补 SSH 教程入口与启动方式；v0.1.3 增补普通/高级两个启动入口、新建文件与文件夹、多选批量操作和独立的预览框）

AWFM（Aimu's Web File Manager）是一个**跑在你自己电脑上**的小工具：它在浏览器里给你一个文件管理器界面，用来浏览和管理**另一台机器**（通常是虚拟机或服务器）上的文件。SSH 连接由你电脑上的后端建立，浏览器里拿不到你的私钥或密码。

**怎么读这份手册**：章节按规划文档 §8 的十二章节目录编排，另加两章 v0.1.1 新增的内容——「在线编辑与文件操作」（第 8 章）与「文件检索」（第 9 章），共十四章。所有命令都在 **Windows PowerShell** 里、在**项目根目录**（即包含 app\ 与 frontend\ 的那个目录）下执行。

**与规划文档 §8 的四点差异**（以实际功能为准）：

1. 第 13 章「卸载与清理」：本项目没有安装程序，不写注册表、不注册系统服务、不设置开机自启，「卸载」实际是「停止程序 + 按需删除运行期数据」。
2. 规划文档 §8 未单列「写操作开关」与「主机密钥变化后的处理」：前者并入第 7 章，后者并入第 5 章。首版**不做**的功能在 1.3 与第 14 章说明。
3. 规划文档 §8 未单列「远端文件检索」：v0.1.1 新增的第 9 章专门讲它。
4. 规划文档 §8 未单列「在线编辑与文件操作」：v0.1.1 新增的第 8 章专门讲它。这一章同时**撤销**了首版「不做在线文件编辑器」的限制（见 1.3）。

## 1 项目介绍

### 1.1 它能做什么

| 能力 | 在界面上的入口 | 说明 |
| --- | --- | --- |
| 管理多条连接 | 左侧「+ 新增」/「编辑」/「删除」 | 每条连接含主机、端口、用户名、认证方式；支持密钥与密码两种认证 |
| 首次连接核对指纹 | 点「连接」时自动弹出 | 目标机未记录过时，必须你确认才会记录（第 5 章） |
| 浏览远程目录 | 路径条「↑」、面包屑、「⟳」 | 进入目录、返回上级、刷新、点表头排序 |
| 预览文本文件 | 双击文件 / 选中后「预览」 | 最多读 256 KiB，二进制文件会被拒绝 |
| 下载文件 | 选中后「下载」 | 走 120 秒票据地址，进度与「另存为」由浏览器负责 |
| 上传文件 | 开启写操作后「上传」 | 可多选；同名文件先确认再覆盖；有进度与取消 |
| 在线编辑文本文件 | 操作列的「编辑」/ 预览里的「编辑」 | v0.1.1 新增：在对话框里改文本并保存，保存前检查别人有没有改过（第 8 章） |
| 重命名 / 压缩 / 解压 / 删除 | 文件列表「操作」列 | v0.1.1 新增：需要先开启写操作；压缩固定产出 .tar.gz（第 8 章） |
| 检索远端文件名 | 文件区上方的搜索栏 | v0.1.1 新增：在当前目录及其子目录里按名称搜（第 9 章） |
| 新建空文件 / 空文件夹 | 工具栏「新建文件」/「新建文件夹」 | v0.1.3 新增：在当前目录里建，不跳转；名称当场校验，重名直接拒绝（§8.8） |
| 复制 / 剪切 / 粘贴 | 操作列「复制」「剪切」，工具栏「粘贴」 | v0.1.3 新增：只记住路径，粘贴时才在目标目录动手；不能粘到别的连接里（§8.9） |
| 多选与批量操作 | 工具栏「多选」 | v0.1.3 新增：行首出现复选框，可批量复制 / 剪切 / 删除 / 压缩 / 解压（§8.10） |
| 独立的预览框与操作区 | 预览对话框、文件列表「操作」列 | v0.1.3 调整：预览内容进自己的框里滚动；七个操作按钮固定在各自的槽位上，用不上的变灰而不消失（§6、§8.5） |

### 1.2 它怎么工作

    浏览器  ──HTTP（仅本机）──▶  AWFM 服务 127.0.0.1:32579  ──ssh -s sftp 子进程──▶  目标机 sshd + sftp 子系统

- 后端只用 **Python 3.12 标准库**，运行期唯一依赖的外部程序是**系统自带的 OpenSSH 客户端**（ssh.exe）。
- 前端是原生 HTML/CSS/JS，没有框架、没有构建步骤、**不引用任何外网资源**，断网也能用（T-002）。
- 服务默认只监听 127.0.0.1（仅本机可访问），这是决策 D-009。

### 1.3 首版不做什么

依据规划文档 §3.2，以下内容**本版明确不做**，请不要按「应该有」去用：

- 不做终端，不做远程命令面板——不能在页面里敲命令；
- 不做用户注册、云端同步、在线账号；
- 不做数据库 / 消息队列 / 微服务 / 前后端分离的后端架构；
- 不做复杂权限平台与多用户协作——一台电脑一个人用；
- 不做自动下载依赖与在线更新。

规划文档 §3.2 里还有一条「不做在线文件编辑器」。**v0.1.1 按任务书 2.md 的第四阶段撤销了这一条**：现在可以在浏览器里改远端文本文件的内容并保存（见第 8 章）。撤销的同时补上了数据安全约束——只允许可识别的文本文件、有大小上限、保存前重查写权限、发现别人改过就拒绝覆盖。

写操作方面：**v0.1.0 只有「上传 / 覆盖」**；v0.1.1 起增加了在线编辑保存、重命名、压缩成 .tar.gz、解压（.tar.gz / .tgz / .tar / .zip）与删除；**v0.1.3 起再增加新建空文件与空文件夹、复制 / 剪切 / 粘贴、多选批量操作**（见第 8 章）。**仍然没有**的是修改权限、打包下载、跨连接搬运（复制与移动只在同一条连接内部进行）。所有写操作都要求先在连接上开启「允许写操作」，并且服务端会独立复核一遍——界面上的按钮灰不灰不作数。

### 1.4 几个名词

| 名词 | 意思 |
| --- | --- |
| 目标机 | 你通过 SSH 连上去的那台机器（虚拟机、服务器） |
| 连接（配置） | 一条记录：主机、端口、用户名、认证方式等，保存在 data\config.json |
| 主机密钥 / 指纹 | 目标机的「身份证」，显示成 SHA256:... 的样子 |
| 信任库 | 本项目的 data\known_hosts 文件，只记录你亲自确认过的目标机密钥 |
| 会话 | 连接成功后，后端与目标机之间的那条 SSH 通道 |
| 票据（ticket） | 下载用的限时入口，120 秒内有效，只能下载你点的那一个文件 |
| 写操作 | 上传与覆盖，默认关闭，需要你显式打开 |

## 2 系统要求

| 项目 | 要求 | 实测情况 |
| --- | --- | --- |
| 操作系统 | Windows 11 x64 | 阶段 01 实测：Windows 11 家庭版 26300 / AMD64，普通用户，**无管理员权限** |

## 3 快速开始

### 步骤 1（推荐）生成配置文件

在项目根目录执行：

    python app\main.py --init-config

成功后输出三行：

    已生成配置文件：E:\Project\aimus-web-file-manager\data\config.json
    请编辑该文件，填入你的虚拟机地址与登录信息。
    提示：私钥认证需要 identity_file 指向私钥文件；密码不会也不应写入这个文件。

如果 data\config.json 已经存在，会输出「生成配置失败：配置文件已存在，未做任何修改。」——这是有意的：**--force 会覆盖它并丢掉你已有的连接配置**。

### 步骤 2（可选）手工预填一台机器

不填也能启动：程序启动后你可以在界面左上角点「+ 新增」填表单，程序会自己把结果写回 data\config.json。若想直接改文件，用记事本打开：

    notepad data\config.json

把 connections 一节写成（字段含义见第 10 章）：

    "connections": [
      {
        "id": "my-vm",
        "name": "我的虚拟机",
        "host": "192.168.170.128",
        "port": 22,
        "username": "aimu",
        "auth_method": "key",
        "identity_file": "C:\\Users\\Aimu2\\.ssh\\id_ed25519",
        "note": "",
        "allow_write": false
      }
    ]

注意 JSON 里反斜杠必须写成两个（\\），这是 JSON 的转义规则，与 AWFM 无关。

### 步骤 3 启动

双击项目根目录的 **run.bat**（Linux / macOS 是 `./run.sh`）。这是**普通启动**，不用记任何参数：

    AWFM 文件管理器 —— 普通启动
      [ OK ] AWFM 已启动（版本 0.1.3）
        地址：http://127.0.0.1:32579/
        进程：PID 36596（后台运行，关掉本窗口不会停服务）
        访问范围：仅本机（security.allow_lan=false）
        日志：logs\app.log（控制台输出：logs\console.log）
        停止：run.bat stop      查看状态：run.bat status
        浏览器：已用系统默认浏览器打开地址
      [ OK ] 服务已经起来，可以直接用了。
        地址：http://127.0.0.1:32579/
        日志：logs\console.log（应用日志：logs\app.log）
        停止：在项目目录运行 stop（例：run.bat stop）
        看完按回车关闭这个窗口；关掉它不影响后台服务。

它依次做四件事：找 Python（版本不够会说清需要什么）→ 拒绝重复启动 → 启动服务并**等 `/api/health` 真的通过** → 才用**系统默认浏览器**打开地址。几条要知道的行为：

- **浏览器打不开不算启动失败**：窗口会打印地址并留住等你看，退出码仍是 0。把地址复制到浏览器即可。
- **不会起第二个实例**：已经在跑时直接打开地址，并告诉你停止方法。
- **起不来时窗口不会一闪而过**：先打印失败原因，再打印控制台日志路径，然后停在那里等你按回车。
- **自动化里调用**：`set AWFM_NO_PAUSE=1` 跳过「按回车」，`--no-browser` 是**唯一**不打开浏览器的开关（配置里的 `open_browser` 与旧选项 `--open-browser` 自 v0.1.3 起不再影响启动）。

需要菜单、端口/参数、诊断、状态、日志、安全停止与重启时，用**高级启动**（见下一节）。

### 步骤 3.1 高级启动

双击 **run-advanced.bat**（Linux / macOS 是 `./run-advanced.sh`）进入交互菜单：

    AWFM 启动器
      目录：E:\Project\aimus-web-file-manager
      地址：http://127.0.0.1:32579/
      状态：没有运行
      1) 后台启动    2) 前台启动（Ctrl+C 停止）    3) 状态    4) 停止    5) 日志    6) 自检    7) 退出

两份脚本做的事完全一样，只是**不带参数时**的默认动作不同：普通入口直接起服务（等价于 `quick`），高级入口进菜单（等价于 `menu`）。带参数时两者都原样透传，脚本会自动切到自己的目录，双击与命令行行为一致：

    run-advanced.bat start                 后台启动（默认）
    run-advanced.bat start --foreground    前台启动，按 Ctrl+C 停止
    run-advanced.bat check                 只做启动前自检，不启动服务
    run-advanced.bat status / stop / logs  看状态 / 停止 / 看日志尾部

菜单里选「后台启动」或者用 `start` 命令，**同样会在服务就绪后自动打开浏览器**；要关掉就加 `--no-browser`。

启动成功的实测输出：

      [ OK ] AWFM 已启动（版本 0.1.3）
        地址：http://127.0.0.1:32579/
        进程：PID 36596（后台运行，关掉本窗口不会停服务）
        配置：E:\Project\aimus-web-file-manager\data\config.json
        访问范围：仅本机（security.allow_lan=false）
        日志：logs\app.log（控制台输出：logs\console.log）
        停止：run.bat stop      查看状态：run.bat status

开发时等价的前台入口是 `python app\main.py`；**项目自身的选项**（`--init-config`、`--check`、`--log-level` 等）仍走它——run.bat 只转交启动器自己的选项（`--port`、`--config`、`--foreground`、`--no-browser`、`--force`、`--yes`…），把别的参数交给它会被拒绝。前台运行的横幅：

      AWFM 0.1.3 已启动
      请在浏览器打开：http://127.0.0.1:32579/
      （仅本机可访问。需要局域网访问请修改配置中的 security.allow_lan）
      按 Ctrl+C 停止

> 什么都不带直接双击 run.bat 时，如果它发现当前不是交互终端（例如被脚本调用），会立刻打印用法与状态并退出，不会挂着等你输入。

### 步骤 4 打开浏览器

普通启动成功时浏览器已经被自动打开了（高级启动的 `start` 也一样）；没打开就手动访问 http://127.0.0.1:32579/ 。看到左侧「连接」列表就成功了。第一次打开时如果列表是空的，页面会提示「还没有配置任何连接。点右上角「+ 新增」，填入虚拟机的地址与登录方式。」。端口不是 32579 时，以启动器打印的「地址：」为准。

### 步骤 5 自检

`run.bat check`（两个入口都支持；不启动服务，检查 Python、配置文件、ssh 客户端、数据/日志目录可写、端口是否空闲）。更细的项目自检是第 3.1 节的 `python app\main.py --check`，启动器在自检末尾也会提示去跑它。

### 停止

普通入口（`run.bat`）与高级入口（`run-advanced.bat`）接受同一套命令，下面统一写作 `run.bat`，换成 `run-advanced.bat` 效果相同；Linux / macOS 上把 `run.bat` 换成 `run.sh`。

- **后台启动的**（`run.bat start`）：用 `run.bat stop`。启动器只停止自己记在 `data\awfm.pid` 里的那个进程，不会去动别的程序。后台进程收不到 Windows 的温和停止信号，所以它会先问「是否强制终止 PID N」，你答 y 才强制结束；不是交互终端时一律当作拒绝（`run.bat stop --force --yes` 供自动化用）。
- **前台启动的**（`run.bat start --foreground` 或 `python app\main.py`）：在窗口里按 **Ctrl+C**，会打印「正在停止……」，断开所有 SSH 会话，不留孤儿 ssh 进程（验收项 T-013）。直接关窗口不保证走完这套清理，所以建议用 Ctrl+C。
- 想确认状态或看日志：`run.bat status`、`run.bat logs`（默认最后 40 行，`-n 100` 可加长，`--follow` 持续跟踪）。

### 常用命令行参数

| 参数 | 作用 |
| --- | --- |
| （不加参数） | 用 data\config.json 启动；该文件不存在时用内置默认值启动并提示 |
| --init-config | 生成默认配置文件后退出 |
| --force | 与 --init-config 连用：覆盖已存在的配置文件（会丢连接配置） |
| --check | 只做环境与配置自检，不启动服务 |
| --config PATH | 改用指定配置文件；该文件不存在会直接报错，不会用默认值兜底 |
| --host ADDR | 覆盖 server.host（仍要过 allow_lan 检查） |
| --port PORT | 覆盖 server.port（必须是 1..65535，否则报「端口号必须在 1..65535 之间。」） |
| --log-level LEVEL | 覆盖 security.log_level（DEBUG/INFO/WARNING/ERROR/CRITICAL） |
| --no-browser | 启动后**不**打开浏览器（v0.1.3 起默认就会打开，这是唯一的关闭开关；旧选项 --open-browser 仍被接受但已无作用） |
| --version | 打印版本后退出（实测输出：`AWFM 0.1.3`） |

| ssh 可执行文件 | 找到的 ssh 客户端路径 | 找不到 → 「[ 失败 ] 找不到 ssh 可执行文件」；路径不像已存在的文件 → 「[ 警告 ] ssh 路径看起来不寻常」 |
| 前端资源 | 详情行是 frontend 目录 | 缺 index.html → 「[ 失败 ] 前端缺少 index.html」；目录不存在 → 「[ 失败 ] 前端资源目录不存在」 |
| 数据目录可写 / 日志目录可写 | 程序会在这两个目录里各写一个临时探针文件（.awfm-write-test）再删掉，用来证明真的可写 | 不可写 → 「[ 失败 ] 数据目录不可写」并附上系统错误原因 |
| 主机密钥信任库 | 详情行是 data\known_hosts 的路径 | 文件还不存在 → 「[ 警告 ] 主机密钥信任库尚未建立」（**还没连过任何机器时属于正常**，详情写着「会在首次确认主机指纹后创建」） |
| 主机密钥策略：strict | 当前策略，见 D-010 与第 5 章 | — |
| 监听地址：127.0.0.1:32579（仅本机） | 将要监听的地址与端口；括号里是「（仅本机）」还是「（允许局域网访问）」 | — |
| 已配置连接：1 个 | 配置文件里现有的连接条数 | — |
| 自检通过（M 项警告）。 | 全部通过（可能有警告）。命令退出码 0 | 有失败时是「自检未通过：N 项失败，M 项警告。」，退出码 1，可用于脚本判断 |

## 4 首次连接

### 4.1 新增一条连接

界面左上角点「+ 新增」，弹出「新增连接」表单（旁边还有一个「扫描」按钮，用来让工具自己去虚拟机网络里找一台，见 4.4）：

| 字段 | 怎么填 | 留空或填错会怎样 |
| --- | --- | --- |
| 名称 | 只是给你自己看的标签 | 留空时自动用「用户名@主机」 |
| 主机 | **必填**：IP 或域名，例如 192.168.170.128 | 空着提交会提示「请填写主机地址。」；含非法字符会被后端拒绝 |
| 端口 | 目标机 sshd 的端口，默认 22 | 必须是 1..65535 的整数 |
| 用户名 | 目标机上的登录账号，例如 aimu | 表单允许留空，但留空等于把用户名交给 ssh 自己猜（通常是本机的 Windows 用户名），**建议始终填写** |
| 认证方式 | 「密钥（推荐）」或「密码」 | 选密码时下面的私钥字段会隐藏 |
| 私钥文件 | 见 4.2 | 选择密码认证时不需要 |
| 备注 | 随便写，会显示在卡片下方 | 可留空 |
| 允许对该连接执行写操作 | 默认**不勾**（见 7.2） | 不勾时后端拒绝一切写请求 |

保存成功后提示「已新增连接。」或「已保存连接配置。」，并立即写回 data\config.json。

删除一条连接：点卡片上的「删除」，会弹出确认框「要删除连接「<名称>」吗？」并说明「这会从本地配置文件里移除这条记录。远端机器上的文件不会有任何变化。」

### 4.2 用密钥认证（推荐）

**私钥路径怎么写**：在「私钥文件」里填**完整路径**，例如：

    C:\Users\Aimu2\.ssh\id_ed25519

也可以留空——留空时由 ssh 自己去找：ssh-agent 里已加载的密钥，或 %%USERPROFILE%%\.ssh 下的默认密钥。填相对路径时基准是**项目根目录**（不是当前工作目录），所以最省事的做法就是写完整路径。私钥**始终只在本机使用**，不会被发送到浏览器。

**先做这一步：给私钥收紧权限（icacls）**

Windows 版 OpenSSH 对私钥文件的访问权限有要求；权限过于开放时会拒绝使用这把密钥，连接就会失败。下面这组命令只处理**这一个文件**（把主体名换成 whoami 的输出）：

    whoami
    # 记下输出，例如 laptop-sb2oik3d\aimu2
    $key = "$env:USERPROFILE\.ssh\id_ed25519"
    icacls "$key" /inheritance:r
    icacls "$key" /grant:r "laptop-sb2oik3d\aimu2:(R)"

**不要对整个 .ssh 目录（或任何目录）做 /inheritance 或 /grant:r 设置。** 阶段 02 报告记录过一次实测（R-05）：对目录做继承设置后，目录里的文件会变成读不出来；把目录恢复原状要用：

    icacls "<目录路径>" /reset /T /C

**更省事的做法**：私钥直接用 Windows 自带的 ssh-keygen 在本机生成，只把生成的 .pub 文件内容追加到目标机的 ~/.ssh/authorized_keys。这是阶段 02 报告给出的建议做法：

    ssh-keygen -t ed25519 -f "$env:USERPROFILE\.ssh\id_ed25519"

### 4.3 用密码认证

- 认证方式选「密码」，不需要填私钥；
- 点「连接」时弹出输入框，标题是「输入 <用户名@主机:端口> 的密码」，提示「密码只用于这一次连接，不会写入配置文件；断开连接后需要重新输入。」；
- **密码不会被保存**：连接记录里根本没有密码字段（app/models/connection.py 的字段中没有它，依据决策 D-014）。密码只出现在这一次「连接」请求里，交给一次性辅助程序喂给 ssh 子进程，用完立即删除；它不经过命令行参数，也不经过环境变量；
- 密码输错会提示「认证失败，请重新输入密码。」并再给你一次输入框，不需要重新点「连接」。

### 4.4 不填地址：让工具去虚拟机网络里找一台

不知道虚拟机的 IP 时，不用先去 VMware 里翻。点左侧「连接」标题旁的「扫描」，工具会读**这台机器自己的** VMware 状态，把「有哪些虚拟机、谁正开着、哪个地址能连 SSH」列出来。

**它读什么**（全部只读，不碰远端、不改本机 VMware 的文件）：

| 来源 | 用来回答 |
| --- | --- |
| VMware 清单（inventory.vmls） | 这台机器上有过哪些虚拟机 |
| vmrun list | 此刻哪几台在运行（没装 VMware Tools 也能用） |
| 虚拟机的 .vmx | 名称、客户机类型、网卡 MAC |
| vmnetdhcp.conf 与 vmnetdhcp.leases | 虚拟网段有哪些、历史上发过哪些地址 |
| 系统邻居表（Get-NetNeighbor） | 这些网段上现在有哪些地址是活的 |

**三种状态是三件事**，结果表里分开写，别混着看：

- **发现的虚拟机**——清单与配置里有的机器，哪怕它此刻没开机；
- **地址在线**——那个地址有人应答；
- **SSH 可用**——22 端口真的通了，这一台现在就能连。

「探测无响应」不等于关机：可能是防火墙拦了、可能机器没开、也可能只是那一眼没赶上。列出来的地址都只是**候选**。

**操作步骤**

1. 点「扫描」，先看展开的「这台机器上能读到什么」：六条来源各自的状态与说明。写着「需要管理员权限」的那条是正常的——非管理员读不到 VMware 进程的命令行，运行状态改由 vmrun 判断。
2. 点「开始扫描」。状态旁的进度文字会依次走到：正在读清单 / 正在看运行状态 / 正在读虚拟机配置 / 正在读租约 / 正在查邻居表 / 正在探测地址。本机实测约 5 秒；地址多或者有机器不响应时会久一些。
3. 看结果。每台虚拟机一行，列出名称、运行状态、地址（主地址 + 其它线索）、结论（SSH 可用 / 地址在线 / 探测无响应 / 没有地址 / 地址未探测）和备注。
4. 想让哪台成为一条连接，点该行的「创建连接」：地址、端口 22 与一条备注会**预填**进「新增连接」表单——名称、用户名、认证方式还要你自己补，保存与否也由你决定。保存后点「连接」时，仍然要先确认主机指纹（第 5 章）。
5. 想中途停下就点「中止」：正在探测的地址会及时收手，已经读到的部分照样列出来，提示里会写明这是中止前的结果。关掉面板时若扫描还在跑，工具会自动替你请求中止（一次只允许一个扫描）。

**上限与边界**（都可以在配置里调，见 10.2 的 discovery 段）

- 只探测 vmnetdhcp.conf 声明过的虚拟网段内的地址——公网地址、本机网卡地址、网关地址一律不探；
- 每个地址只对 **22 端口**试一次 TCP 连接，默认 1 秒超时；
- 一个网段最多 254 个地址、整轮最多 512 次探测、总时长不超过 60 秒；碰到上限就停下，并在结果里写明停在哪里；
- **不登录**目标机、不执行任何远端命令、不派生 ssh 进程、不修改 VMware 的任何文件，也不往连接表里加任何东西。

为什么只探 22 端口：AWFM 是做 SSH 文件管理的，能连 SSH 才算「可用」。判断方式就是直接对 22 端口建一次 TCP 连接，没有登录，因此不会在目标机留下登录记录。

## 5 主机密钥确认

### 5.1 为什么要有这一步

SSH 用「主机密钥」来确认：你连上的确实是那台目标机，而不是中间转发的人。AWFM 默认策略是 **strict**（决策 D-010）：目标机不在信任库里时**不会自动接受**，而是停下来请你核对。信任库是**项目自有**的 data\known_hosts；程序连 Windows 用户目录下的默认 known_hosts 也一并指向这个文件，避免那儿的老记录把这一步悄悄跳过。

### 5.2 界面上会看到什么

第一次对某台机器点「连接」，会弹出「首次连接，请核对主机指纹」，正文（界面原文）：

> 这是第一次连接 aimu@127.0.0.1:2222。SSH 用主机密钥确认「你连上的确实是那台机器」，而不是中间转发的人。
>
> 请核对下面的指纹与目标机上的输出是否一致（在目标机上执行）：
>
> ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
>
> （指纹列表：每行是密钥类型 + SHA256:...）
>
> 如果指纹对不上，说明中间可能有其他人，请选「取消」。

按钮是「取消」和「指纹一致，信任并继续」。

### 5.3 怎么核对

在**目标机**上执行（需要 root 或能读到主机公钥）：

    ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

把输出的 SHA256:... 与界面上的逐字符对照：

- **一致** → 点「指纹一致，信任并继续」。程序会把该密钥写进 data\known_hosts，提示「已记录主机密钥。」并自动重连一次；
- **不一致** → 点「取消」，先把目标机的身份搞清楚，不要继续。

信任库文件长这样（本项目实测内容）：

    # AWFM 于 2026-10-14T16:29:15Z 由用户确认后加入
    [127.0.0.1]:2222 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIIm7KiAL492I9SLZ9ft9VdZcfRNYoK4K6shnMe3ss5VV

两点说明：

- 端口不是 22 时，主机那一列写成 [主机]:端口；端口是 22 时只写主机名；
- 确认时只信任 ssh 首选的第一个密钥（通常是 ed25519），也就是写进文件的那一个。写入前程序会重新向目标机采集一次密钥，只有与你确认过的指纹一致才会落盘。

### 5.4 指纹变了怎么办

如果目标机的密钥与信任库里的记录不一致，界面会弹出「主机密钥发生变化」，同时列出「本地已记录的指纹」与「目标机现在提供的指纹」（后者高亮），并说明：

> 目标机被重装或换过密钥会出现这种情况；有人在中间转发也会。
>
> 本工具不会自动接受新密钥，也不会替你删除旧记录。确认目标机确实换过密钥后，请手工编辑 data\known_hosts，删掉该主机对应的行，再重新连接。

**界面刻意不提供「一键接受」**：主机密钥变化既可能是你自己重装了系统，也可能是有人在中间转发。做成一键接受，等于把这个判断从你手里拿走。所以这一步是手工改文本文件：

1. 打开文件：notepad data\known_hosts
2. 找到这台机器那一行（形如 [主机]:端口，或裸主机名），**整行删除**
3. 保存，回到界面重新点「连接」——会重新走 5.2 的确认流程

想彻底重来：删掉整个 data\known_hosts，之后每条连接都会重新确认一次。

## 6 文件浏览

- **进入**：连接成功后自动打开该用户的家目录（后端向目标机查询得到），顶部是路径条。
- **返回上级**：路径条左边的「↑」；已经在根目录时它是灰的。路径条里**每一级都可以点**，可以直接跳回去。
- **刷新**：「⟳」。另外连接状态每 20 秒自动刷新一次（页面切到后台时跳过）。
- **排序**：点表头「名称 / 大小 / 类型 / 修改时间」。同一个表头再点一次反向；换到别的列时，大小与修改时间默认从大到小，其余默认从小到大。**目录永远排在最前面**，然后是符号链接，最后是普通文件；同一类型内部才按你选的列比较，完全相等时按名称。
- **打开**：**双击**目录进入；**双击**文件进入预览；双击符号链接会先问一次目标类型——指向目录就进入，指向文件就预览，断链会显示「（断链）」。单击只是选中这一行。
- **每一行显示**：名称（带图标）、大小（目录显示「—」）、类型、权限（rwx 三段）、修改时间、操作。
  这几列自 v0.1.3 起是**各自独立的固定列**：名称占剩下的全部宽度、过长时用省略号截断（悬停或键盘聚焦看完整名，右键菜单里还有「复制完整路径」），大小 / 类型 / 权限 / 修改时间为受控宽度，表头与每一行用同一套列定义，窗口变窄时先按断点收掉次要列，不会把「操作」挤到名字上面去。
- **条目太多**：单个目录最多显示 5000 项；超出时顶部公告条提示「这个目录的条目太多，只显示前 N 项（共 M 项）。」
- **预览**：文本文件直接看，**最多读 256 KiB**。
  v0.1.3 起预览内容放在**自己的框里**（带边框、内边距与深色主题背景），标题栏写文件名与状态，正文区**在框内滚动**，所以长文本不会把模态框撑破，也不会带动整页滚动；换行与缩进原样保留。超出时提示「文件大于预览上限，下面只显示了前 N 的内容（编码按 X 解析）。」；像二进制的文件会被拒绝，提示「该文件看起来是二进制文件，无法作为文本预览。」；不是 UTF-8 的文本会按 latin-1 显示并提示「这个文件不是 UTF-8 文本，按 X 显示。」。预览窗口里有「下载」按钮，可以直接转去下载；v0.1.1 起还有一个「编辑」按钮，可以直接转去在线编辑（预览本身始终只读，见第 8 章）。
- **多连接**：可以同时连多台（上限 ssh.max_sessions，默认 4，见第 10 章）。切换连接时视图会复位到「/」并清空列表，不会把上一条连接的目录残留下来。
- 页面右上角的「?」按钮随时可以打开界面自带的「使用说明」。

## 7 文件传输

### 7.1 下载

- 选中一个文件 → 点「下载」（预览窗口里也有）。文件型条目才能下载；目录会提示「目录不能直接下载。」，首版不提供打包下载。
- 从用户角度看：点完立刻开始，**进度和「另存为」都在浏览器自己的下载栏里**，与 AWFM 界面无关。
- 背后发生了什么（对用户意味着什么）：浏览器直接发起的下载请求带不了 AWFM 的会话令牌，所以界面先用带令牌的请求换一张**票据**，再把票据拼进下载地址。票据的特点：
  - 有效期 **120 秒**——过期了重新点一次「下载」即可；
  - 只对**这一次的文件**和**这一条连接**有效，换成别的文件或连接都不认，会提示「下载票据无效、已过期，或与请求的文件不匹配。请回到界面重新点击下载。」；
  - 只存在内存里，程序重启后全部失效；
  - **不是一次性的**：如果你在「另存为」里取消了、或浏览器重试，同一个地址仍然可用（这是有意的，否则取消一次就得重来）。
- 下载大小默认**不限**（security.max_download_bytes = 0 表示不限）。如果你设了上限，超限的文件会提示「该文件超过了配置的下载大小上限。」
- 中途断网或关掉页面：服务端日志里记一条「下载被客户端中断」，不算错误；如果实际发出的字节数与文件大小不一致，服务端会主动断开，而不是**悄悄**给你一个不完整的文件。

### 7.2 上传（需要先开启写操作）

**开启写操作**：工具栏上的「允许写操作」默认是关的。勾选时会弹出确认框：

> 要为「<连接名>」开启写操作吗？
>
> 开启后这条连接可以上传并覆盖远端文件。默认关闭，是为了先确认只读浏览足够稳定。

点「开启」才生效，提示「已开启写操作。」；再取消勾选会写回配置，提示「已关闭写操作。」

**关着的时候**：界面上不会给你写入入口，点了「上传」也会被后端拒绝，提示「这条连接没有开启写权限，无法上传。」——后端对所有写请求一律拒绝。

**上传流程**：点「上传」→ 选文件（可多选）→ 逐个处理：

1. 先问后端：这个文件名在远端目录里是否已存在；
2. 远端已有**同名目录** → 提示「「<名字>」在远端是一个目录，无法用文件覆盖。」并跳过；
3. 远端已有**同名文件** → 弹出「覆盖远端文件」确认框，写明远端现有文件的大小与最后修改时间，以及「覆盖后旧内容无法恢复。」；不确认就跳过这个文件；
4. 弹出进度框：「正在上传 <名字>：NN%（已传 / 总）」，按钮「取消上传」；按 **Esc**、点对话框外面、点「取消上传」都等于取消（不会出现「进度条没了但还在偷偷传」）；
5. 结束提示：「上传完成：N 个文件，跳过 M 个。」；取消时提示「已取消上传 <名字>。」并停止后续文件。

**覆盖是怎么做的（值得知道）**：**新建**上传时，文件先以临时名字传（文件名带 .awfm-part- 与一段随机后缀），传完再改名成正式名字——所以新文件要么完整出现，要么完全不出现；而**覆盖**只能直接截断写入（SFTP v3 的改名不能替换已存在的目标文件），如果覆盖途中被取消或断网，远端会留下一个不完整的文件。这是首版明确接受的取舍。

**其他限制**：

- 单个文件默认上限 security.max_upload_bytes = 2147483648 字节（2 GiB），0 表示不限；超限提示「上传的文件超过了配置的大小上限。」
- 上传的**文件名里不能带 .awfm-part-**（否则会干扰临时文件机制，直接被拒绝）。

## 8 在线编辑与文件操作

v0.1.1 新增。这一章讲两件事：**改远端文本文件的内容**，以及**重命名 / 压缩 / 解压 / 删除**。它们都要求这条连接先开启写操作（见 7.2），并且服务端会独立复核写权限——界面上的按钮状态只是提示，不是依据。

### 8.1 打开编辑器

- **入口一**：在文件列表里选中一个文件，点工具栏的「编辑」。
- **入口二**（更顺手）：双击文件打开预览，用预览窗口里的「编辑」按钮。预览本身**始终是只读的**，窗口里也写着这句话，不会因为你在预览里做了什么就改动远端。
- **哪些文件能编辑**：只有**普通文件**，而且内容要是可识别的 UTF-8 文本。目录、符号链接（按它指向的文件处理）、二进制文件（含 NUL 或大量控制字符）、编码不是 UTF-8 的文件、超过大小上限的文件都会被拒绝，并给出具体原因。
- 编辑器是一个独立对话框，标题里写明文件路径；打开时会读一次远端内容，并把这次读到的**大小、修改时间、SHA-256、编码、换行风格**记下来当基线。

对话框里显示：路径、大小（含上限）、修改时间、编码（有字节顺序标记 BOM 时会写明）、换行（LF / CRLF / CR，混合换行会标注）、当前字符数与估算字节数。底部状态行写着「已修改，尚未保存」或「与打开时一致」，保存按钮只在**有改动、且这条连接开着写操作**时才可点。

### 8.2 保存、换行与 BOM

- 点「保存」或按 **Ctrl+S** 提交。保存成功后对话框关闭，列表里这一行的大小与修改时间会自动刷新。
- **换行风格原样保留**：打开时是 CRLF 的，保存后还是 CRLF；是 LF 的还是 LF。你粘贴进来的内容里混着别的换行也不会改变这个风格。
- **BOM 也保留**：原来有 UTF-8 BOM 的就写回 BOM，原来没有的就不加，你不需要自己处理。
- 空文件可以编辑并保存；没有末尾换行的文件保存后仍然没有末尾换行——AWFM 不会顺手替你补一个换行。
- **大小上限**：security.max_edit_bytes，默认 2097152 字节（2 MiB）。它比上传上限小得多，因为内容要整块放进浏览器。超限的文件读不出来也保存不了，提示「这个文件超过了在线编辑的大小上限。」
- **写盘顺序**：新内容先写成临时文件（名字带 .awfm-part- 与一段随机后缀），确认字节数无误后再改名替换原文件；替换前会先把原文件改名备份，替换失败时尝试回滚。保存失败时**你敲的内容还在编辑器里**，不会因为一次失败就丢掉。
- 保存过程中断线：请求直接失败，对话框里显示错误，不会出现「以为保存成功、其实没写进去」的情况。

### 8.3 别人改过这个文件（冲突）

保存时 AWFM 会先核对基线：

- 文件在你编辑期间被别的程序改过（另一个终端里的 vim、另一台机器上的脚本、你自己的另一次上传）→ **拒绝写入**，提示「为了不覆盖别人的修改，AWFM 没有写入。…」，并多出一个「重新加载远端内容」按钮；你敲的内容留在文本框里。
- 这时你有两个选择：点「重新加载远端内容」拿别人的版本重来（你的修改会被替换，请先自己复制出去），或者关掉对话框、把自己写的内容存到别处再重新打开。
- 文件在你编辑期间被删除 → 保存时提示「文件已不存在，无法保存。」；文件变成了目录 → 提示目标是一个目录。

### 8.4 取消与放弃修改

- 「取消」、按 **Esc**、点对话框外面的空白处、点右上角的 **×**：这四种关法走同一套检查——没有改动就直接关闭；有改动会先在对话框里问一句「有未保存的修改，确定放弃吗？」，点「放弃修改并关闭」才丢，点「继续编辑」回到编辑器。**任何一条关掉的路径都不会悄悄丢掉你敲的内容**（v0.1.1 阶段六 CU 验收时发现并修复：原先只有「取消」按钮会问，Esc 与点外面会直接关闭）。
- 刷新页面或关掉页面同样不会保存——编辑内容只在浏览器内存里。

### 8.5 重命名与删除

「操作」列里的按钮按**固定顺序**排列（v0.1.3 §1）：**编辑 → 复制 → 剪切 → 重命名 → 删除 → 压缩 → 解压**。
同一个操作在任何一行都出现在同一个位置、宽度一致、文字居中；当前条目用不上的操作不会消失，而是**变灰并说明原因**（悬停看提示），这样切换目录、切换文件类型时按钮位置不会跳动。

下面先说重命名与删除（都需要写操作）：

- **重命名**：弹出对话框，预填当前名字，输入新名字后确定。同一个目录里已有同名条目时会拒绝；名字里不能带斜杠，也不能是单独的一个点或两个点。改名只作用于你点中的那个条目——**重命名一个符号链接改的是链接本身，不会动它指向的文件**。
- **删除**：先弹一次确认框（标题是「删除条目」或「删除目录」）。删除一个**非空目录**时，AWFM 会先停下来说明里面有多少个条目，需要你再确认一次「连同内容一起删除」才会递归删除。删除空目录与单个文件只要一次确认。
- 删除同样**不跟随符号链接**：删掉一个链接，它指向的文件或目录还在。
- 删除与重命名都**不能作用于根目录**。
- 删除不可撤销：远端通常没有回收站。

### 8.6 压缩与解压

- **压缩**：点「压缩」，对话框预填「名字.tar.gz」。产出固定是 **.tar.gz**（GNU tar + gzip）。目录会连内容一起打包；包里的成员保留原来的权限与修改时间；**符号链接以链接本身入包**，不会把目标内容塞进去。名字里已经带 .tar.gz / .tgz / .tar / .zip 的按你填的原样使用。
- **解压**：点「解压」，支持 **.tar.gz、.tgz、.tar、.zip**。目标目录默认是压缩包所在的目录，可以改成别的绝对路径（不存在时只创建最后一级）。远端已存在的同名文件默认**跳过**并在结果里列出，勾选「覆盖已有文件」才会覆盖。
- 结果提示里会写明解出了多少个文件、多少个目录、跳过了什么。压缩包条目数超过 10000 或解出的总字节数超过 512 MiB 时会停下，已经解出来的部分保留，提示里说明停在哪一步。
- **安全策略**：压缩包里出现绝对路径、上跳段、NUL 或符号链接条目时——越界的条目**整包拒绝**（不是悄悄跳过），符号链接与硬链接直接跳过并在结果里列出。压缩包里的内容不会被当成可执行的东西。

### 8.7 边界与限制

- **不在远端执行任何命令**：压缩与解压都在本机进程内流式完成，远端只看到普通的 SFTP 读写。
- 写权限关闭时，操作列里的重命名 / 压缩 / 解压 / 删除是灰的；即使绕过界面直接请求接口，服务端也会返回「该连接未开启写权限」。
- 只读文件（没有写位）保存会被拒绝，提示里带权限位；上传可以覆盖它，那是上传接口自己的语义。
- 一次只处理一个条目：单条流程（编辑器、上传、下载）。需要成批处理时用第 8.10 节的多选，或第 8.9 节的复制 / 剪切 / 粘贴。
- 上传中途取消会留下不完整的文件（覆盖上传的既有取舍，见 7.2）；在线编辑保存不受影响，因为保存走「临时名 + 改名」。

### 8.8 新建文件与文件夹（v0.1.3 新增）

工具栏上有「新建文件」和「新建文件夹」两个按钮，两者都要求**已连接**且这条连接**开启了写操作**，否则按钮是灰的。

- 点开是一个对话框：写明要在哪个目录里建什么、输入名称，按钮是「创建」与「取消」。回车提交，Esc 取消。
- 名字的要求：不能为空、不能是 `.` 或 `..`、不能带 `/`（那是一条路径而不是一个名字）、不能有空字符、最多 255 个字符。界面上是**即时报错**（对话框里直接显示原因），服务端还会**再校验一遍**——前端能拦住不等于安全。
- **同名一律拒绝，绝不覆盖**：对话框里会显示「同名条目已经存在」以及现有条目的类型。后端用的是**排他创建**（打开文件时带 O_EXCL 语义、建目录本身就是排他的），而不是「先查有没有、再建」——两次系统调用之间被人抢先时，后者会变成一次静默覆盖。
- **建完停在当前目录**，不会自动跳进新文件夹；列表会立刻刷新并选中新条目。新建的空文件是 **0 字节**，可以直接点「编辑」写内容。
- 权限：新建文件是 `0644`、新建文件夹是 `0755`，实际生效的值还会被远端的 umask 影响。
- 「建好了」与「列表刷新到了」是两件事：如果创建成功但刷新失败，提示会写「已创建……列表没能刷新：……请点「刷新」确认一下」，不会把一次刷新失败说成创建失败（否则你会再建一次，得到两个同名文件）。
- 常见的拒绝与含义：

  | 提示 | 原因 | 怎么办 |
  | --- | --- | --- |
  | 同名条目已经存在 | 当前目录已经有这个名字 | 换一个名字，或先改名/删除旧的 |
  | 该连接未开启写权限，无法新建文件 | 工具栏的「允许写操作」没勾 | 勾上并确认 |
  | 新建文件：远端拒绝访问 | 远端目录的权限位不允许你写 | 换目录，或在远端 `chmod` |
  | 连接已断开 | SSH 通道掉了 | 重连后再建，别以为文件已经建好 |
  | 新建文件的目标不是目录 | 当前路径在远端已经不是目录 | 刷新列表后重试 |

### 8.9 复制、剪切与粘贴（v0.1.3 新增）

- 行内「操作」列的「复制」「剪切」，以及多选操作条上的同名按钮，都只是**在本地记下路径**（记的是「哪条连接上的哪些路径」），**真正的字节搬运发生在粘贴那一刻**——所以复制一个几 GB 的目录不会立刻开始搬。
- 进入目标目录，点工具栏的「粘贴」（剪贴板空的时候它是灰的）：
  - **复制**：源保留，目标目录里出现副本。目录会连整棵子树一起复制（上限：单批 10000 个条目、512 MiB，以及目录深度上限），**符号链接跳过**并在提示里说明跳过了几个——复制链接的目标内容会让人误以为那是新文件。
  - **剪切**：等价于移动。移动是逐项改名，**不覆盖**已存在的目标：目标已存在时会拒绝，源保持原样。移动目录时它必须还在原处。
  - 目标里已经有同名条目时，复制会整批停下并问你「要覆盖它们吗？」——确认后才覆盖，覆盖无法撤销；剪切不会问，直接拒绝。
- **不能跨连接粘贴**：两台机器上的同一条路径不是同一个东西。剪贴板会记着来源连接，换一条连接后「粘贴」是灰的。
- 不能「复制到自己里面」、也不能在同一个目录里粘贴（前后两种都会被拒绝并说明原因）。

### 8.10 多选与批量操作（v0.1.3 新增）

- 点工具栏的「多选」进入多选模式：每一行**最前面出现复选框**，按钮文字变成「退出多选」（再点一次会清空勾选并退出）。只是切换界面状态，不会重新加载列表，所以滚动位置不会跳。
- 勾选方式：点复选框，或者多选模式下**点行本身**（整行都是可点区域）。表格上方的操作条会显示「已选 N 项」，并给出**全选 / 复制 / 剪切 / 删除 / 压缩 / 解压 / 清空**。
- 批量动作：
  - **删除**：一次确认，删除整批（目录连同内容）。中途失败时提示里会写明「已处理哪几项、失败的路径是哪一段、原因是什么」——不会假装全成功，也不会让你重头猜。
  - **压缩**：勾多项时打成一个 `.tar.gz`（默认名字 `archive.tar.gz`，可以改）。
  - **解压**：只对勾选里的**压缩包**生效（勾选里没有压缩包时按钮是灰的）；其他条目会被忽略。
  - **复制 / 剪切**：把整批放进剪贴板，然后去目标目录粘贴。
- 多选模式不影响单条流程：编辑器、上传、下载仍是单条语义。

## 9 文件检索

> v0.1.1 新增。检索在**服务端**跑，浏览器只负责显示进度与结果；列目录仍然只走既有的 SFTP 通道，**不会在远端执行任何命令**。

### 9.1 怎么搜

- **入口**：文件区工具条下方是搜索栏（输入框 + 「搜索」按钮）。输入关键词，回车或点按钮即可。
- **范围**：**从当前目录往下**，含全部子目录。搜索栏右边的范围文案会写明，例如「范围：/home/aimu 及其子目录」；还没搜过时显示「范围：当前目录及其子目录」。想换范围就先用路径条切到别的目录再搜。
- **匹配规则**：按**名称**匹配（文件名或目录名都可以命中），**大小写不敏感**——搜 `report` 能命中 `Report.md`、`REPORT.TXT`；中文同样有效。是**包含**匹配（`报告` 能命中 `报告-草稿.txt`），不是前缀匹配；不支持通配符与正则，也**不搜文件内容**。
- **一次一个**：同一条连接同一时刻只能有一个检索在跑。没等它结束就再点搜索，会提示「这条连接上已经有一个正在进行的搜索」，先「中止」或等它跑完即可。

### 9.2 结果怎么看

- 每一行给出**名称、类型（目录 / 文件 / 符号链接）、所在目录、大小、修改时间**；把鼠标停在一行上还能看到完整路径。
- 排序固定为**目录 → 符号链接 → 文件**，同类里按名称升序（所以「名字看起来一样」的目录和文件会先列目录）。目录的大小显示「—」。
- **定位**：点某一行右边的「定位」（双击整行同效）。左侧文件列表会跳到该行所在的目录、选中它并高亮一下。**结果面板不会关闭**，可以接着点下一条。若该文件刚被改动过而列表里找不到它，会提示「已切到「X」，但列表里没有「Y」」。
- **清空**：点「清空」把面板收起、输入框清空、结果行删除；左侧列表不受影响。

### 9.3 进度、中止与「没有匹配」

- **进度**：搜索时状态显示「搜索中…」，右边是「已扫描 N 个目录 · M 个条目 · 命中 K 条 · 用时 x.x 秒」，每 0.7 秒刷新一次。
- **中止**：搜索进行中会出现「中止」按钮，点了之后状态变「已中止」，**已经找到的结果仍然留在表里**。中止不算失败，也不算结果被截断；中止后可以立刻发起下一次搜索。
- **没有匹配 vs 搜索失败**：这是两件不同的事——没有命中会明确写「没有匹配的文件。」；真正的失败（搜索根不存在、连接断开、权限不足、超时）会显示错误码与原因。
- **读不到的目录**：会被跳过并计数，面板提示「有 N 个目录读不到（权限不足或已被删除），已跳过。」，搜索继续。只有连续多个目录都读不到时才会整体失败。
- **符号链接**：只报告、不跟随。指向目录的链接不会被钻进去，因此自指的目录环不会让搜索转圈，也不会顺着链接跑到你给的搜索根之外。

### 9.4 上限与边界

- 一次检索的预算：命中 **500** 条、目录 **2000** 个、条目 **100000** 个、总时长 **45** 秒。任一触发都会写明「……（上限），搜索提前结束。」并保留已经找到的结果。
- 连接断开时，正在跑的检索会被停掉，状态显示失败原因；切换连接或断开连接会清空结果面板，只保留当前连接的结果。
- 检索只在你给的那个目录往下走，不越过它，也不跟随 `..` 或符号链接跳出范围。
- 服务端只保留最近若干次（20 次）**已结束**的检索记录，更早的记录过期后再查询会提示「搜索不存在或已过期」。

## 10 配置管理

### 10.1 文件在哪、怎么改

| 事项 | 说明 |
| --- | --- |
| 默认位置 | data\config.json（相对**项目根目录**，与你在哪个目录敲命令无关） |
| 生成 | python app\main.py --init-config；已存在时报「配置文件已存在，未做任何修改。」，加 --force 才会覆盖（会丢连接配置） |
| 换一个文件 | python app\main.py --config D:\awfm\config.json；该文件不存在会直接报「指定的配置文件不存在：…」，不会用默认值兜底 |
| 界面改动 | 新增 / 编辑 / 删除连接会**立刻**写回该文件（原子写入，写一半断电不会留下半个文件） |
| 生效时机 | 配置只在启动时读一次，手工改完**要重启程序** |
| 写坏了 | **拒绝启动**并指出行号列号：「配置文件不是合法的 JSON，已停止启动。」+ 详情，**绝不**自动重建、也不拿默认值覆盖（决策 D-006）——你所有的连接都在这个文件里 |
| 模板 | config\config.example.json 与程序内置默认值一致（单元测试会断言两者同步） |

### 10.2 字段说明

三类字段共用一个规则：**类型不对**报「配置项 <字段> 必须是整数/布尔值/字符串。」，**数值越界**报「配置项 <字段> 超出允许范围。」（详情里写「要求 a..b，实际 v」）。

**server 段**

| 字段 | 类型 | 默认值 | 取值范围 | 改了会发生什么 |
| --- | --- | --- | --- | --- |
| host | 字符串 | 127.0.0.1 | 非空；非回环地址必须同时 allow_lan=true | 决定服务只对本机开放还是对局域网开放；为空报「配置项 server.host 不能为空。」；非回环且 allow_lan=false 时报「拒绝绑定到非回环地址，因为 security.allow_lan 未开启。」 |
| port | 整数 | 32579 | 1..65535 | 浏览器地址要跟着改；被别的程序占用时启动报「启动失败：127.0.0.1:32579 已经被占用。」（启动器）或「端口 32579 已被占用。」（程序自身） |
| open_browser | 布尔 | false | true / false | 启动后自动打开浏览器（命令行 --open-browser / --no-browser 可临时覆盖；`run.bat start --no-browser` 同样生效） |
| request_timeout_seconds | 整数 | 60 | 5..3600 | **本版已在配置层校验，但代码里还没有使用点**（单次 HTTP 请求超时尚未据此实现），保留字段 |

**security 段**

| 字段 | 类型 | 默认值 | 取值范围 | 改了会发生什么 |
| --- | --- | --- | --- | --- |
| allow_lan | 布尔 | false | true / false | 设为 true 才允许把服务开放到局域网（server.host 写 0.0.0.0 等才生效）。**风险自负**：本版没有为局域网访问增加额外身份验证（见第 11 章） |
| host_key_policy | 字符串 | strict | 只允许 strict 或 accept-new | strict：目标机未记录时停下来让你确认（第 5 章）；accept-new：首次自动接受。取值非法报「配置项 security.host_key_policy 取值非法。」 |
| session_token_ttl_seconds | 整数 | 43200 | 60..604800 | **本版已在配置层校验，但代码里还没有使用点**（令牌是每次启动重新生成的），保留字段 |
| max_upload_bytes | 整数 | 2147483648（2 GiB） | 0..10995116277760（10 TiB）；0 = 不限 | 单个上传文件的大小上限；超限提示「上传的文件超过了配置的大小上限。」 |
| max_download_bytes | 整数 | 0（不限） | 0..10995116277760（10 TiB）；0 = 不限 | 单个下载文件的大小上限；超限提示「该文件超过了配置的下载大小上限。」 |
| max_edit_bytes | 整数 | 2097152（2 MiB） | 1024..67108864（64 MiB） | v0.1.1 新增：在线编辑单个文件的大小上限。内容要整块放进浏览器，所以默认比上传上限小得多；超限的文件既读不出来也保存不了，提示「这个文件超过了在线编辑的大小上限。」当前值也会出现在 GET /api/session 的响应里 |
| log_level | 字符串 | INFO | DEBUG / INFO / WARNING / ERROR / CRITICAL（大小写不敏感） | 决定写进 logs\awfm.log 的详细程度；非法值报「配置项 security.log_level 取值非法。」 |
| redact_secrets | 布尔 | true | true / false | true 时日志会经过脱敏过滤器，避免把凭据类内容写进日志文件；改成 false 后日志里可能出现更多原文 |

**ssh 段**

| 字段 | 类型 | 默认值 | 取值范围 | 改了会发生什么 |
| --- | --- | --- | --- | --- |
| connect_timeout_seconds | 整数 | 15 | 1..600 | 传给 ssh 的 ConnectTimeout；目标机不通时大约这么久之后报「连接 <主机>:<端口> 超时，无法获取主机密钥。」或连接超时错误 |
| command_timeout_seconds | 整数 | 60 | 1..3600 | 单次 SFTP 操作的超时；越大越能容忍慢机器，但出错时等待也更久 |
| keepalive_interval_seconds | 整数 | 30 | 0..3600（0 = 关闭） | 传给 ssh 的 ServerAliveInterval，用来在网络静默时保持会话 |
| max_sessions | 整数 | 4 | 1..64 | 同时活动的 SSH 会话上限；超过时程序自动回收**最久没活动**的那条会话（日志里会写「活动会话数达到上限 N，回收最早的会话 x」） |
| known_hosts_file | 字符串 | data/known_hosts | 相对项目根的路径，或绝对路径 | 信任库文件的位置；删掉它等于让所有主机重新确认一次 |
| ssh_executable | 字符串 | ""（自动查找） | 空串或 ssh.exe 的完整路径 | 空串时按「PATH → C:\Windows\System32\OpenSSH\ssh.exe」查找；指定了不存在的文件会报「配置中指定的 ssh 可执行文件不存在。」 |
| sftp_executable | 字符串 | "" | — | **本版已在配置层校验，但代码里还没有使用点**：连接层用 ssh -s sftp 起 SFTP 子系统，不单独调用 sftp.exe，保留字段 |

**discovery 段**

v0.1.1 新增（阶段五：在线虚拟机自动发现）。整段都可以不写，不写时按默认值走。

| 字段 | 类型 | 默认值 | 取值范围 | 改了会发生什么 |
| --- | --- | --- | --- | --- |
| enabled | 布尔 | true | true / false | false 时「扫描」入口不可用，点了会提示「在线虚拟机发现在配置里是关闭的。」 |
| probe_ssh | 布尔 | true | true / false | false 时只报告「地址是哪来的」，一个包都不发（结果里所有地址都是「未探测」） |
| probe_timeout_seconds | 数字 | 1.0 | 0.1..5.0 | 单个地址的 TCP 探测超时（秒）。越小扫描越快，但慢机器会被误判成「无响应」 |
| max_probe_workers | 整数 | 16 | 1..64 | 并发探测的线程数；调大只在本机网络上更快，不会探得更远 |
| max_addresses_per_subnet | 整数 | 254 | 1..4096 | 每个虚拟网段最多探测多少个地址 |
| max_probes | 整数 | 512 | 1..65536 | 整轮扫描最多探测多少个地址（所有网段合计） |
| time_budget_seconds | 整数 | 60 | 1..3600 | 整轮扫描的时间上限；到点后停下，用结果里的 truncated_reason 说明还剩多少没探 |
| vmware_root | 字符串 | "" | 空串或路径 | VMware 的安装目录（找 vmrun.exe）；留空时自动查注册表 |
| vmware_data_dir | 字符串 | "" | 空串或路径 | VMware 的数据目录（清单与 vmnetdhcp.* 的所在处）；留空时自动找当前用户的 AppData 与 ProgramData 下的 VMware 目录 |

**connections 段**

必须是数组（否则报「配置项 connections 必须是数组。」）；其中每一条的字段：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| id | 字符串 | 界面新增时自动生成 | 只能含字母、数字、下划线、连字符，不能以连字符开头，最长 64；重复时报「连接 id 重复：<id>。」；在界面上**不能修改 id** |
| name | 字符串 | 空（自动用 用户名@主机） | 显示名 |
| host | 字符串 | 无（必填） | 主机名或 IP |
| port | 整数 | 22 | 1..65535 |
| username | 字符串 | "" | 目标机登录账号；最长 128 |
| auth_method | 字符串 | key | 只允许 key 或 password |
| identity_file | 字符串 | "" | 私钥文件路径（见 4.2） |
| note | 字符串 | "" | 备注 |
| allow_write | 布尔 | false | 是否允许对该连接做写操作（上传 / 覆盖）；界面上勾「允许写操作」即为 true |
| created_at / updated_at | 字符串 | "" | 时间戳，程序维护 |

一条不合法的连接会整体报「第 N 条连接配置不合法。」并在详情里说明原因（未知字段、缺必需字段等）。

## 11 故障排除

先看**日志**，再看这张表。

### 11.1 日志在哪、怎么调级别

| 问题 | 答案 |
| --- | --- |
| 日志文件 | logs\awfm.log（相对项目根目录） |
| 日志同时在终端 | 前台运行（`run.bat start --foreground` 或 `python app\main.py`）时直接打在窗口里；后台启动时启动器把控制台输出写进 logs\awfm-console.log，用 `run.bat logs` 看 |
| 滚动策略 | 单个文件到 2 MiB 就换新文件，保留 3 个备份（也就是最多约 8 MiB） |
| 行格式 | 2026-10-15 10:00:00 INFO    [awfm.api.handlers] 消息 |
| 目录建不出来 | 只警告，不阻止启动（终端里会说明） |
| 怎么改级别 | 改 data\config.json 里 security.log_level（DEBUG/INFO/WARNING/ERROR/CRITICAL），重启程序；或临时用 python app\main.py --log-level DEBUG |
| 想看得最细 | --log-level DEBUG：SFTP 层会输出更多诊断信息（细节见 docs/DEVELOPMENT.md） |
| 日志会不会泄密 | 默认 redact_secrets=true，日志会经过脱敏过滤器 |

### 11.2 症状 → 原因 → 处理

| 症状（界面或终端原话） | 可能原因 | 怎么处理 |
| --- | --- | --- |
| 启动失败：127.0.0.1:32579 已经被占用。（启动器）/ 端口 32579 已被占用。（程序自身） | 上一次的 AWFM 还在运行，或别的程序占了 32579 | 先 `run.bat status` 看是不是 AWFM 自己在跑：是就 `run.bat stop`；不是就换端口（改 server.port，或 `run.bat start --port 9000`）。查占用者：`netstat -ano | findstr :32579`（Linux：`ss -ltnp | grep :32579`） |
| 拒绝停止：PID N 的映像名是 xxx.exe，不是 python 进程。 | PID 文件里的进程号已经被系统回收、分配给别的程序了 | 启动器为此**故意拒绝**停止；确认 AWFM 确实没在运行后删掉 data\awfm.pid 再重试 |
| 已放弃：没有做任何强制操作。 | 后台进程收不到温和的停止信号，启动器问「是否强制终止」时你答了 n，或当前不是交互终端（自动当作拒绝） | 在交互窗口里重跑 `run.bat stop` 并答 y；或确认那个 PID 就是 AWFM 后 `run.bat stop --force --yes`（会连同它的子进程一起结束） |
| [失败] 找不到 Python 解释器。（run.bat 打印） | 系统没装 Python，或安装时没勾 "Add python.exe to PATH" | 装 Python 3.10+ 并勾选 PATH，装完重开一个命令行窗口再跑 run.bat |
| 找不到系统 ssh 客户端，AWFM 没有它就登不上远程主机。 | 系统没有 OpenSSH 客户端 | 安装「OpenSSH 客户端」功能；或把 ssh.exe 的完整路径填进 ssh.ssh_executable |
| 启动失败：找不到 ssh 客户端程序。 | 系统没有 OpenSSH 客户端，或者它不在 PATH 与默认路径里 | 安装「OpenSSH 客户端」；或把 ssh.exe 的完整路径填进 ssh.ssh_executable |
| 启动失败：配置中指定的 ssh 可执行文件不存在。 | ssh.ssh_executable 写错了路径 | 改成空串（自动查找）或改成正确路径 |
| 启动失败：拒绝绑定到非回环地址，因为 security.allow_lan 未开启。 | server.host 写了 0.0.0.0 之类的地址，但没开 allow_lan | 改回 127.0.0.1；确实要开放局域网就把 allow_lan 改成 true 并了解风险（第 11 章） |
| 启动失败：无法绑定到地址 <地址>。 | server.host 写了一个不属于本机的地址 | 改回 127.0.0.1，或写本机真实网卡地址 |
| 启动失败：配置文件不是合法的 JSON，已停止启动。 | 手工编辑 config.json 时漏了逗号/引号 | 按详情里的「第 X 行第 Y 列」修好再启动；程序**不会**自动重建这个文件，以免丢掉你的连接 |
| 启动失败：指定的配置文件不存在：… | --config 的路径写错了 | 检查路径；或先 --init-config 生成一份 |
| 提示：未找到 …\data\config.json，本次使用内置默认值。 | 还没生成配置文件 | 正常现象；想固化配置就执行 python app\main.py --init-config |
| 页面上出现「缺少会话令牌，已拒绝。」/「会话令牌不正确，已拒绝。」 | 服务重启过（令牌每次启动都会重新生成），旧页面还开着 | 刷新页面（F5）即可；令牌只存在于页面里 |
| 连接失败：认证失败：目标机拒绝了提供的凭据。 | 密码错；密钥没有被目标机接受；用户名写错 | 密码认证会再弹一次输入框；密钥认证请确认目标机 ~/.ssh/authorized_keys 里有你的公钥，且用户名正确 |
| 首次连接时反复弹指纹确认 | 你点了「取消」；或指纹确认后写入失败 | 核对无误后点「指纹一致，信任并继续」；确认 data\known_hosts 可写 |
| 连接失败：<主机> 的主机密钥与本项目信任库中的记录不一致。 | 目标机重装/换过密钥；或者真的有人在中间转发 | 按 5.4 手工删掉 data\known_hosts 里那一行再重连 |
| 连接失败：连接 <主机>:<端口> 超时，无法获取主机密钥。 | 目标机没开机、sshd 没启动、端口没开放、被防火墙拦住 | 先在目标机上确认 sshd 在跑、端口在监听；WSL 环境要先在 WSL 里启动 sshd |
| 权限不够（提示 permission denied / 403） | 目标机上的这个账号对路径没有权限 | 换用有权限的账号或目录；AWFM 不会绕过目标机的权限 |
| 该路径不存在。 | 文件被删了，或路径是软链接指向的目标没了 | 刷新一下目录再看 |
| 该连接未开启写权限，无法上传文件。 | 这条连接没勾「允许写操作」 | 在连接卡片上打开「允许写操作」（会二次确认，见 7.2） |
| 该连接未开启写权限，无法保存文件。/ 无法重命名… | 这条连接没勾「允许写操作」 | 同上。界面上的按钮灰着只是提示，服务端对每个写请求会再查一遍 |
| 文件在你编辑期间被改动过，保存被拒绝。 | 别的程序（或另一次上传）在你打开编辑器之后改了同一个文件 | 点编辑器里的「重新加载远端内容」拿最新内容重来；你敲的内容还在文本框里，必要时先复制出去（见 8.3） |
| 这个文件看起来不是文本文件，不能在线编辑。/ 这个文件的编码不是 UTF-8，无法安全地在线上编辑。 | 选中的是二进制文件，或文本编码不是 UTF-8 | 二进制文件请下载后用本地工具处理；需要转编码也在本地转好再上传 |
| 这个文件超过了在线编辑的大小上限。 | 文件大于 security.max_edit_bytes（默认 2 MiB） | 调大 max_edit_bytes（上限 64 MiB），或下载后本地编辑再上传（见 10.2） |
| 该连接尚未建立会话。请先在界面上点击「连接」。 | 服务重启过，或这条连接断了 | 重新点「连接」 |
| 这个文件太大，无法在浏览器里预览。 | 文件超过 256 KiB 的预览上限 | 直接下载下来看 |
| 上传的文件超过了配置的大小上限。 | 单文件超过 max_upload_bytes（默认 2 GiB） | 调大 max_upload_bytes（0 = 不限），或换个方式传输 |
| 资源不存在。/ 前端缺少 index.html / 前端资源目录不存在 | 项目文件不完整（比如只拷了 app\ 没拷 frontend\） | 用完整的项目目录运行；自检 python app\main.py --check 会指出缺哪一块 |
| 数据目录不可写 / 日志目录不可写 | 目录被占用、只读，或盘满 | 检查目录属性与磁盘空间；自检会再次提示 |

**把「程序的问题」和「目标机的问题」分开**：先用系统自带的 ssh 手工连一次目标机（把端口、用户、主机换成你的）：

    ssh -p 2222 aimu@127.0.0.1

如果这条也连不上，问题在目标机或网络，与 AWFM 无关。

从这一步往下逐层排查（服务端 sshd、客户端环境、认证方式、虚拟机网络）请用配套教程 `docs/SSH_SETUP_GUIDE.md`：它的 J 节给了 16 类报错的**原文**、可能原因、检查顺序与安全修复方向，L 节是一份 8 步快速排查清单加一页速查表；教程里凡未在本机实测过的命令都带【需管理员】或【未验证】标记（决策 D-021），附录 B 汇总了验证范围。

## 12 安全注意事项

| 主题 | 现状与要求 |
| --- | --- |
| 监听范围 | 默认**只监听 127.0.0.1**（仅本机可访问）。开放局域网必须显式写 security.allow_lan=true（D-009），而且本版**没有**为局域网访问实现额外的身份验证——请保持 false，除非你清楚后果 |
| 会话令牌 | 服务每次启动都会重新生成一个随机令牌，注入首页；除 /api/health 外，所有接口都必须带这个令牌，否则报「缺少会话令牌，已拒绝。」 |
| 跨站防护 | 请求的 Host 必须是本机地址（防 DNS 重绑定）；浏览器的跨站请求会被拒绝（校验 Sec-Fetch-Site 与 Origin）；OPTIONS 预检一律 403，且不返回任何跨源许可头 |
| 密码 | **从不写入磁盘**（D-014）：连接记录里没有密码字段，密码只在一次连接请求里出现，用完即弃；断开后重连需要重新输入 |
| 私钥 | 只在本机使用，不会发送到浏览器；请按 4.2 收紧文件权限 |
| 主机密钥 | 默认 strict + 项目自有信任库（D-010）；变化时**不自动接受**，必须人工处理（5.4） |
| 日志 | 默认脱敏（redact_secrets=true）；但日志仍可能包含主机名、用户名与路径，分享日志前请自行检查 |
| 下载票据 | 120 秒有效、绑定连接与文件、只存内存、进程重启失效 |
| 写操作 | 默认关闭；开启后这条连接可以上传并**覆盖**远端文件。建议只对自己有权限、且能承受误覆盖的目录开启 |
| 目标机账号 | 建议用**专用的非 root 账号**并把可写目录限制在你需要的范围内（本项目集成测试床就是用非 root 用户 aimu 运行的 sshd） |
| 联网行为 | 除「本机浏览器 ↔ 本机服务」与「本机服务 ↔ 你配置的目标机」之外，程序不访问网络；前端不引用任何外网资源（T-002） |

## 13 卸载与清理

AWFM **没有安装过程**：不写注册表、不注册 Windows 服务、不设置开机自启，所以「卸载」= 停止程序 + 按需删除运行期数据。

**1. 停止程序**

在运行服务的窗口按 **Ctrl+C**，看到「正在停止……」即已退出；此时所有 SSH 会话都已断开。

**2. 运行期产生了什么**

| 位置 | 内容 | 删掉的后果 |
| --- | --- | --- |
| data\config.json | 你的连接配置（**没有密码**） | 删掉后程序用内置默认值启动，连接需重建 |
| data\known_hosts | 你确认过的目标机指纹 | 删掉后每条连接会重新确认一次指纹 |
| data\testbed\ | 本项目集成测试用的私钥（只有做集成测试才有） | 不影响日常使用 |
| logs\awfm.log（及 .1 / .2 / .3） | 运行日志 | 无影响 |
| .temp\ | 临时脚本与探针 | 无影响 |

**3. 只清理日志**（保留配置）：

    Remove-Item logs\*.log* -Force

**4. 彻底移除**

确认要删除的路径**就是你项目的路径**（不要删错盘），然后：

    Remove-Item E:\Project\aimus-web-file-manager -Recurse -Force

或者直接在资源管理器里删掉整个项目文件夹——程序在系统里没有留下别的东西。

## 14 常见问题

**能直接在浏览器里编辑远端文件吗？**
能（v0.1.1 起）。选中一个文本文件点「编辑」，改完保存即可。保存前 AWFM 会重查写权限，并检查这个文件在你编辑期间有没有被别的程序改动过——改过就拒绝写入，由你决定是重新加载别人的版本还是先把自己的内容留好。二进制文件、非 UTF-8 文本和超过 security.max_edit_bytes（默认 2 MiB）的文件会被拒绝，不会硬塞进编辑器。详见第 8 章。

**能开终端、执行远程命令吗？**
不能。本版不做终端与远程命令面板，也**不在远端执行任何命令或脚本**（压缩与解压都是本机进程内流式完成的）。写操作目前是：上传 / 覆盖、在线编辑保存、重命名、压缩成 .tar.gz、解压、删除；**没有**新建目录、修改权限、打包下载。

**能从别的电脑访问这个界面吗？**
默认不能：服务只监听 127.0.0.1。要开放需要把 server.host 改成 0.0.0.0（或本机网卡地址）**并且**把 security.allow_lan 改成 true；本版没有为这种用法增加额外的身份验证，请自行评估风险。

**密码存在哪里？**
任何地方都不存（D-014）。输入一次用于当次连接，断开即丢。

**私钥会被上传或发给浏览器吗？**
不会。私钥只在启动 ssh 子进程时由本机的 ssh 程序读取。

**需要联网吗？**
不需要。前端不引用任何外网地址，后端只用 Python 标准库与系统 OpenSSH。

**能同时连几台机器？**
默认最多 4 条活动会话（ssh.max_sessions 可调，1..64）。达到上限时会自动回收最久没活动的那一条，日志里有记录。

**为什么刷新页面后还能继续用，重启服务后却要刷新？**
会话令牌是**每次启动**重新生成的，并写在首页里。服务重启后旧页面上的令牌就失效了，刷新页面拿新的即可。

**下载为什么要先换一张票据？**
因为浏览器自己发起的下载请求没法带 AWFM 的令牌。票据让下载地址本身临时有效（120 秒），既不用把令牌暴露在地址里，也不影响浏览器原生的进度与「另存为」。

**为什么覆盖上传中途取消会留下半个文件？**
SFTP v3 的改名不能替换已存在的文件，所以覆盖只能直接截断写入。新建上传有「临时名 + 改名」保护，覆盖没有。这是首版明确接受的取舍。

**run.bat 和 scripts\launcher.py 是什么关系？**
run.bat（Linux / macOS 是 run.sh）是唯一入口，双击就出菜单：启动 / 状态 / 停止 / 日志 / 自检。它自己只做三件事——切到脚本所在目录、找到 Python、把参数原样转给 scripts\launcher.py；真正的逻辑（PID 文件、端口检查、健康检查、停止阶梯、日志尾部）都在启动器里，两个平台共用同一份实现。开发时也可以 `python app\main.py` 前台跑，它等价于 `run.bat start --foreground`。

**界面上的「?」按钮是干什么的？**
打开界面自带的使用说明，里面是「怎么用」与「关于安全」两组，和本手册第 6、7、8、9、12 章的内容一致。
